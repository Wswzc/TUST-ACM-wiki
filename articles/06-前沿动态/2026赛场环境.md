# 2026 赛场环境：gnu++20、关掉的 AI，以及模板里不该追的新语法

> 读完你应该能：知道 2026 年 ICPC World Finals（迪拜）公开的评测配置里 C++ 是什么；把「语言标准又出了新版本」和「下场区域赛能不能用」分开；更新队内模板前先读**当届当站**的环境说明，而不是追博客里的 C++26 特性清单。
>
> 一句口号：**赛场只认评测机那一行 `g++` 命令；新标准是选修，通不过编译的优雅等于 0 分。**

## 背景 / 为什么要读这篇

[`06-前沿动态`](../../README.md) 这栏不是科技新闻联播。TUST-ACM 算法实验室要跟的「前沿」，首先是**赛场真实环境往哪挪**：编译器、语言标准、IDE 里那只 AI 开没开、现场几台电脑。

语言委员会可以一年发一版。OJ、区域赛、世界赛各自有镜像，速度差好几年。实验室有人在 CF 用了 `std::ranges` 觉得真香，上场 CCPC 评测机 `gnu++14` 直接 CE；有人把 Cursor 的补全手感当成决赛标配。本篇用 **2026 年 7 月 ICPC 公布的 World Finals 环境稿**当锚点，再讲国内训练该怎么折中。配置会改，改了以官网为准。

## 正文

### 1. 2026 世界赛这张快照（会过期）

来源：[ICPC Programming Environment](https://icpc.global/worldfinals/programming-environment)（页面写明 *subject to change*；本文对照的是 2026-07-28 那一版更新说明）。

| 项 | 2026 WF 稿 |
| --- | --- |
| 系统 | Ubuntu 24.04 LTS，Xfce |
| C++ | **g++ 13.2.0**，` -O2 -std=gnu++20 -static` |
| C | gcc 13.2.0，`gnu11` |
| Java | OpenJDK 21 |
| Python | **只有 Python 3**（PyPy3），Python 2 已从世界赛消失 |
| Kotlin | 1.9.x |
| 电脑 | **一队一台**（传统赛制，不是每人一台） |
| IDE 里的 AI | **关闭**：Eclipse / CLion / VS Code 等内部 AI 工具 disabled |
| 提交 | 评测机按上面的 flags 编，不走 Microsoft C++ |
| 参考资料 | 机器上有 STL 文档等；不能假设有外网 |

另外：欧洲赛区 2026 EUC 的公开环境写过 g++ 14.2、`-std=c++23`，和世界赛**不是同一张表**。不要用「欧洲能 C++23」去推断迪拜或国内区域赛。

国内 ICPC 区域赛、CCPC、省赛、校赛的编译命令写在**当站技术说明 / 气球须知 / 训练场环境**里。可能是 `c++14`、`c++17` 或 `c++20`。洛谷、Codeforces、AtCoder 又是各自一套（CF 长期提供 G++20 / G++23 等选项，**选错语言等同换编译器**）。

### 2. 对实验室模板意味着什么

[第 0 周](../00-团队指南/第0周-Windows下g++与A+B交题.md) 要求本地有 g++。2026 年建议：

1. **默认按 `gnu++17` 写队内公共模板**，需要时再开 20。理由：17 覆盖结构化绑定、`<bits/stdc++.h>` 习惯、大多数 STL；国内不少评测机仍停在 14/17。17 能过的代码，20 的评测机几乎也能过。反过来不成立。
2. **世界赛 / 明确写了 `gnu++20` 的场次**，可以在纸质模板里用：`std::gcd`（17 就有）、`bool` 向量要注意、`structured bindings`。`ranges`、`concepts`、模块 `import`、`std::print` 仍然**不要**当默认武器——占纸、难默写、对拍机不一定有。
3. **C++23 / C++26 的新库**当假期阅读，不进赛时 U 盘。评测机没有的头文件，博客再新也是 CE。
4. **`__int128`、`__builtin_popcountll`** 是 GNU 扩展，在 `gnu++` 下通常可用，MSVC 和部分严格 `-std=c++20`（无 gnu）可能没有。世界赛命令是 `gnu++20`，国内若写死 `c++17` 也可能仍是 GNU 方言——仍以当站为准。
5. 编译命令对齐评测机：本地至少会敲  
   `g++ -O2 -std=gnu++20 -static a.cpp -o a`  
   不要只会按 IDE 绿三角。世界赛评委按命令行编，不是按 CLion 的配置。

[矩阵快速幂](../03-算法竞赛/矩阵快速幂.md) 里用的 `__int128` 取模，在这份 WF 稿的 g++ 上没问题；换 Java 就要自己写大整数或换算法。

### 3. AI 被关掉，和训练的关系

同一页写了：现场 IDE **内部 AI 关闭**。没有外网。这不是「组委会落伍」，是赛制：比的是队伍在一台电脑上的设计和实现。

训练含义，和 [竞赛里怎么用 AI](../05-AI工具/竞赛里怎么用AI.md) 同一条线，2026 年只是把规则写得更白：

- 日常用 Cursor 解释 CE、造数据，可以。
- 周训至少有一场**关掉补全**，三人一台机，模拟决赛带宽。
- 不要把「IDE 能生成整份 Dinic」当成区域赛能力。纸质模板 + 默写，才是上场的那份。

Python 2 从世界赛消失，提醒另一件小事：语言也有退役。实验室若还有人用 Python 交题，确认是 3、确认当站是 CPython 还是 PyPy、确认递归深度和常数——别用训练 OJ 的 AC 直接推断现场。

### 4. 怎么跟「前沿」而不被牵着跑

值得跟：

- 当届 WF / 区域赛环境页（每年夏秋会改一版）
- 本场 Codeforces / AtCoder 的编译器列表
- 队内 g++ 版本别比评测机**新到用了对方没有的头文件**

不必跟：

- 每年 CppCon 的全部新提案
- 「某框架 2026 年取代 C++」类标题
- 把模块化、协程写进签到题模板

知识库这栏以后若补「某标准落地了」，请写清：**哪家 OJ、哪场区域赛已经能用**，而不是「ISO 通过了」。ISO 通过不等于气球机通过。

## 常见坑 / 注意事项

- **CF 过了 = 区域赛过。** 语言选项不同。  
- **本机 CLion 默认 MSVC。** 世界赛评委不用它。  
- **模板里 `std::ranges::sort`。** 老 `g++` CE。  
- **以为决赛能联网问模型。** 环境页写了没外网、AI 关。  
- **环境页会改。** 赛前再打开一次官方链接，不要只读本篇日期。

## 趣味课间：实验室经典翻车集

- **「我开了 C++23，代码更短。」** 短给评测机看，它说 CE。  
- **热身赛用 Python 过了签到，正赛第一题 TLE。** PyPy 常数和递归，热身数据小。  
- **三人围着一台笔记本，习惯了每人一台外加语音模型。** 决赛是一台、无网、无 AI。周训不练，上场抢键盘会吵。  
- **把 `__int128` 交进 Java 模板仓库。** 语言都换了还在粘 C++。

## 小结

2026 世界赛稿：g++ 13.2、`gnu++20`、一队一台、IDE 内 AI 关闭、没有 Python 2。国内场次自己读技术说明。队内模板默认 17 能编过，20 当加法；23/26 当课外书。训练要把「无网、无 AI、抢一台机」练进肌肉。

建议接着：

- 打开当届环境页，对照本机 `g++ --version` 和编译命令  
- 用 `gnu++17` 和 `gnu++20` 各编一次队内模板，看有没有 CE  
- 下一场训练关补全、三人一台机一小时

工程向仍见 [后端实习词汇表](../02-编程方向/后端实习词汇表.md)。竞赛模板继续补 [强连通分量](../03-算法竞赛/强连通分量.md)、[矩阵快速幂](../03-算法竞赛/矩阵快速幂.md)。
