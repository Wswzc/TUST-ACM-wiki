# 写作规范

> 这是投稿前必读的约定。按同一套格式写，第 1 篇和第 1000 篇才能被同样检索、同样阅读。

## 为什么需要规范

知识库会一直写下去。没有统一格式，后人打开一篇文章会先花时间猜结构，而不是直接学内容。规范只约束**怎么写**，不约束**写什么**。

## 文件与目录

| 项 | 约定 |
| --- | --- |
| 格式 | 一律 Markdown（`.md`） |
| 文件名 | 中文或英文均可，简短、能看出主题。例如 `并查集入门.md` |
| 不要用的文件名 | `新建文档.md`、`未命名.md`、纯数字、过长句子 |
| 存放位置 | 放到 README 里对应的分类目录，不要堆在根目录 |
| 图片 | 放到 `assets/images/`，文中用相对路径引用 |
| 一篇一事 | 一个文件只讲清楚一件事。题目再拆成新文章 |

推荐路径示例：

```text
articles/03-算法竞赛/并查集入门.md
assets/images/dsu-path-compression.png
```

## 文章头部（Front Matter）

每篇文章开头必须有 YAML 头，方便以后做索引和检索：

```yaml
---
title: 并查集入门
author: 你的名字
date: 2026-08-28
category: 03-算法竞赛
tags: [并查集, 数据结构, 图论]
level: 入门
status: 已完成
---
```

字段说明：

| 字段 | 怎么填 |
| --- | --- |
| `title` | 和正文一级标题一致 |
| `author` | 真名或队内常用花名 |
| `date` | 首次发布日期 `YYYY-MM-DD` |
| `category` | 必须是 README 里的七个分类之一 |
| `tags` | 3～5 个关键词 |
| `level` | `入门` / `进阶` / `高级` |
| `status` | `草稿` / `已完成`。草稿也可以入库，但要在 INDEX 里标明 |

## 正文结构

默认按模板来，允许按主题增删小节，但建议保留这几块：

1. **导语**：一句话说清读者能得到什么
2. **背景**：为什么值得读
3. **正文**：分小节，层层推进
4. **常见坑**：你踩过的、别人容易踩的
5. **小结**：收束 + 下一步读什么
6. **参考资料**：有出处就写出处

标题层级：

- 全文只有一个一级标题 `#`
- 用 `##`、`###` 组织内容，不要跳级（例如不要从 `#` 直接到 `###`）

## 代码与公式

- 代码块必须标明语言：`cpp`、`python`、`bash` 等
- 竞赛代码优先给**能编译、能交题**的最小示例，不要只贴碎片
- 行内代码用反引号：`cin`、`printf`
- 复杂度用 `$O(n \log n)$` 或纯文本 `O(n log n)` 均可，同一篇文章内保持一致

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    return 0;
}
```

## 文风

- 写给**下一届还没进实验室的同学**看，少用只有自己懂的缩写；必须用时第一次写出全称
- 结论先行，再给推导或例子
- 用「我们」而不是「笔者」；指出错误时对事不对人
- 不要把整本教材搬进来。讲清楚一件事，再链到下一篇

## 引用与原创

- 题解、论文、博客、官方文档：给出标题和链接
- 代码若来自他人模板，注明来源；改过的写清改了什么
- 不要整篇复制外部文章。转述、压缩、补上队内经验

## 投稿检查清单

发布前过一遍：

- [ ] 头部字段齐全，`category` 填对了
- [ ] 文件名能看出主题，放在正确目录
- [ ] 导语能独立说明「读完能得到什么」
- [ ] 代码能看懂，竞赛代码尽量可运行
- [ ] 有出处的内容已标注
- [ ] 已在 [`INDEX.md`](../../INDEX.md) 登记

## 小结

规范是为了让第 1000 篇仍然好找、好读。拿不准结构时，直接复制 [`templates/article-template.md`](../../templates/article-template.md)。
