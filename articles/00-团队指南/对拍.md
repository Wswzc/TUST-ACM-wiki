# 对拍：让暴力给正解当评测机

> 读完你应该能：在 Windows 终端里用数据生成器 + 暴力 + 正解循环比对输出；知道对拍测的是「小数据上是否一致」，不是复杂度；避免让 AI 同时生成「一模一样的两份代码」然后宣称对拍过了。
>
> 一句口号：**样例太小、系统测太大；中间那一截用随机数据和暴力填上。**

## 背景 / 为什么要读这篇

[第 0 周](第0周-Windows下g++与A+B交题.md) 能本地喂样例。[贪心](../03-算法竞赛/贪心入门.md)、[数位 DP](../03-算法竞赛/数位DP.md)、[线性基](../03-算法竞赛/线性基.md) 都说过：样例过了不等于对。区域赛里你看不到系统数据，能做的是自己当评测机。

TUST-ACM 算法实验室有人 WA 了二十发还在改常数；有人对拍脚本比完发现两份都是错的——因为从同一段生成代码复制了两遍。本篇给一套 **Windows + g++** 的最小闭环。Linux / macOS 把 `.\gen.exe` 换成 `./gen` 即可。

## 正文

### 1. 三份程序

| 文件 | 职责 | 要求 |
| --- | --- | --- |
| `gen.cpp` | 打印一组合法输入 | 小 n，覆盖边界：n=1、全相等、有 0 |
| `brute.cpp` | 暴力 / 短代码 / 另一种写法 | 你相信它对，O(n²) 也行 |
| `sol.cpp` | 准备交的正解 | 只多优化，不少边界 |

对拍通过：**同一份输入，两份输出逐字节（或逐 token）相同。** 失败时留下 `in.txt`，这是最值钱的样例。

暴力必须独立：另一个人写、或你用完全不同的算法（枚举子集 vs 线性基，DFS vs DP）。[竞赛里怎么用 AI](../05-AI工具/竞赛里怎么用AI.md) 可以让模型写 `gen`，**不要**让它根据 `sol` 再「生成一份等价暴力」——它会抄同一处错。

### 2. 生成器要合法、要丑

```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
    mt19937_64 rng(chrono::steady_clock::now().time_since_epoch().count());
    int n = (int)(rng() % 8) + 1;  // 1..8，给暴力留命
    cout << n << '\n';
    for (int i = 0; i < n; i++)
        cout << (rng() % 10) << " \n"[i == n - 1];
    return 0;
}
```

题面有树，就生成 n-1 条边连成树，不要随手 `n` 条环。有模数，输出范围要在题面内。多组数据就生成 T=1 或很小的 T，免得暴力先 TLE。

「丑」：全 0、全相同、已经有序、逆序、重复值。随机平均数据打不中的坑，边界会。

### 3. Windows 最小脚本

假设三个 exe 和脚本在同一目录。PowerShell：

```powershell
g++ -O2 gen.cpp -o gen.exe
g++ -O2 brute.cpp -o brute.exe
g++ -O2 sol.cpp -o sol.exe
for ($i = 1; $i -le 200; $i++) {
    .\gen.exe > in.txt
    Get-Content in.txt -Raw | .\brute.exe > a.txt
    Get-Content in.txt -Raw | .\sol.exe > b.txt
    if (Compare-Object (Get-Content a.txt) (Get-Content b.txt)) {
        Write-Host "mismatch on round $i"
        break
    }
    if ($i % 50 -eq 0) { Write-Host "ok $i" }
}
```

`Compare-Object` 对文本行比较。输出末尾多空行、多空格也会报不同——和 OJ 一样挑剔是好事，交题前用 `'\n'` 统一换行。若只想比 token，写成自己的 `fc` 或短 Python：按空白拆开再比。

停下来之后：**先看 `in.txt`。** 手算或再跑一遍。修 `sol`，不要先修脚本。

Git Bash / MSYS：

```bash
g++ -O2 gen.cpp -o gen
g++ -O2 brute.cpp -o brute
g++ -O2 sol.cpp -o sol
for i in $(seq 1 200); do
  ./gen > in.txt
  ./brute < in.txt > a.txt
  ./sol < in.txt > b.txt
  if ! diff -q a.txt b.txt >/dev/null; then
    echo mismatch $i
    break
  fi
done
```

现场电脑若只有评测机环境，对拍是训练课的事。赛时至少保留手造小数据的能力：n=3 全列出来。

### 4. 对拍说了什么、没说什么

| 过了 200 组小数据 | 没说 |
| --- | --- |
| 小 n 逻辑多半对 | 大 n 的溢出、TLE、精度 |
| 边界若写进 gen | 没写进 gen 的边界 |
| 两份独立实现一致 | 同一份错抄两遍 |

浮点题对拍要 eps，不要 `diff` 全文。输出顺序不唯一的题（任意解）不能直接比字符串，要比「是否都合法」或规定一种规范化。

[莫队](../03-算法竞赛/莫队.md)、[高斯消元](../03-算法竞赛/高斯消元.md) 这类：暴力 n≤10，对拍专门打 `add`/`del` 和主元交换。

## 常见坑 / 注意事项

- **生成器 n 开到 1e5，暴力先死。**  
- **`sol` 多组没清，暴力清了。** 对拍会抓到，这是好事。  
- **重定向编码把 UTF-8 BOM 写进 `in.txt`。** 输入第一整数读崩。用上面的简单重定向。  
- **杀毒软件拦连续起 200 次 exe。** 加白名单，或次数改小。  
- **对拍过了就删 `in.txt`。** 失败那组要留着当回归。

## 趣味课间：实验室经典翻车集

- **「样例过了就是对的。」** 样例是出题人的礼貌，不是全集。  
- **两份代码都从对话框一次生成。** 对拍 100% 通过，系统测 100% 同错。  
- **`rand()` 不播种，每轮数据一样。** `mt19937` 用时间播种，或把轮次写进种子。  
- **输出 `Yes`/`YES` 混用，对拍全红，OJ 也红。** 统一大小写。

## 小结

gen 造合法小题，brute 用笨方法，sol 用要交的方法，循环到不一致为止。不一致时读 `in.txt`，不要猜。对拍管正确性的一小截；复杂度和大数溢出仍要自己算。

建议接着：

- 给最近一道 WA 的题写 n≤8 的 `gen`，先拍 50 轮  
- 贪心、DP、线性基各拍一次，养成交之前的肌肉记忆
