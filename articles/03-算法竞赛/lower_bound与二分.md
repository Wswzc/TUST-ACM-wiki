# 在有序的世界里砍半：lower_bound 与二分

> 读完你应该能：在排好序的 `vector` 上用 `lower_bound` / `upper_bound` 查「第一个 ≥ x」「第一个 > x」；能手写一版不会死循环的整数二分；知道「二分答案」和「在数组里找位置」其实是同一颗脑袋。
>
> 一句口号：**二分不是从中间随便砍，是在保证答案还在区间里的前提下砍。**

## 背景 / 为什么要读这篇

[vector 与 sort](../01-编程语言/vector与sort.md) 之后，你已经能把 n 个数排好。下一秒很多人会写：

```cpp
for (int i = 0; i < n; i++)
    if (a[i] == x) { /* 找到了 */ }
```

n = 10 时这很可爱。n = 2×10^5、询问再来 2×10^5 次时，评测机会送你一份 TLE，附赠三小时比赛里「明明会做」的表情。

有序是一种特权。词典按拼音排，你不会从第一页翻到最后一页找「并查集」；猜 1～100 里的数字，你也不会从 1 喊到 100。计算机干的是同一件事，只是它每刀都问：**左半边还有没有答案？没有就丢掉。**

实验室里每年都有同一出戏：有人把 `lower_bound` 用在**没排序**的数组上，样例恰好有序，AC 了样例，正式数据一来 WA 得不明不白。本篇会把这种戏的剧本先写在墙上。

## 正文

### 0. 先玩两分钟：猜数字

裁判心里有一个 1～100 的整数。你每猜一个数，他只回答「小了」「大了」或「对了」。最优策略不是玄学，是：

- 当前可能区间是 `[L, R]`
- 猜中间 `mid`
- 小了就把 `L` 改成 `mid+1`，大了就把 `R` 改成 `mid-1`
- 区间里只剩一个数时，那就是答案

十次以内一定结束：因为 2^10 = 1024 > 100。这就是 `O(log n)` 的体感——对数增长慢得令人安心。把「裁判的回答」换成「数组中间那个元素和 x 比大小」，你就在数组上二分了；换成「砍长度为 mid 的木头够不够 K 段」，你就在答案上二分了。

### 1. 脑子里只装一个问题

后面所有 API、所有手写模板，都在回答变种问题：

> 在一段**已经单调**的东西上，找**第一个让某句话变成真**的位置。

这句话可以是：

| 那句话 | 你在找 |
| --- | --- |
| `a[i] >= x` | 第一个 ≥ x，即 `lower_bound` |
| `a[i] > x` | 第一个 > x，即 `upper_bound` |
| `a[i] == x` | 先 lower 再看是不是真相等 |
| `check(mid) == true` | 二分答案里「第一个可行解」 |

一旦你能把题面翻译成「第一句真话」，循环怎么写就只是实现细节。翻译错了，模板背得再熟也会 WA。

### 2. 先会用 STL：四件套

默认数组**升序**。万能头已经包含 `<algorithm>`。

设 `a = {1, 2, 2, 2, 4, 5}`，我们要查 `x = 2`。

```
下标:  0  1  2  3  4  5
值:    1  2  2  2  4  5
              ↑        ↑
         lower_bound(2)  end
         第一个 ≥ 2
                    ↑
              upper_bound(2)
              第一个 > 2
```

四个函数：

| 函数 | 语义 | 找不到时 |
| --- | --- | --- |
| `binary_search(l, r, x)` | 有没有 x | 返回 `false` |
| `lower_bound(l, r, x)` | 第一个 ≥ x 的迭代器 | 返回 `r`（对 vector 就是 `a.end()`） |
| `upper_bound(l, r, x)` | 第一个 > x 的迭代器 | 同上 |
| `equal_range(l, r, x)` | 一对 `{lower, upper}` | 两个都是 `r` |

完整可跑的查询器：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    vector<int> a = {1, 2, 2, 2, 4, 5};
    int x = 2;

    auto lo = lower_bound(a.begin(), a.end(), x);
    auto hi = upper_bound(a.begin(), a.end(), x);

    if (lo == a.end()) {
        cout << "没有 ≥ " << x << " 的元素\n";
        return 0;
    }

    int pos = (int)(lo - a.begin());  // 下标
    int cnt = (int)(hi - lo);         // x 出现几次
    cout << "第一个 ≥ " << x << " 的下标是 " << pos
         << "，值是 " << *lo << "，x 出现 " << cnt << " 次\n";

    bool has = binary_search(a.begin(), a.end(), x);
    cout << (has ? "确实有 x\n" : "没有恰好等于 x 的\n");
    return 0;
}
```

几条必须长在肌肉里的细节：

- **迭代器不能解引用 `end()`。** `lower_bound` 找不到时返回 `a.end()`，写 `*lo` 是未定义行为，本地可能「碰巧」不崩，评测机 RE。先比较迭代器，再取 `*lo`。
- **下标用减法。** `lo - a.begin()` 得到 `int` 下标。`distance(a.begin(), lo)` 也对，随机访问容器上两者都是 O(1)。
- **`x` 出现次数 = `upper - lower`。** 这是有序数组上统计频次的标准动作，比再扫一遍优雅，也更快。
- **第三个参数类型要匹配。** `vector<long long>` 里不要传一个随手写的 `int` 常量导致比较别扭——养成 `1LL` 和同类型的习惯。
- **必须和排序用同一套比较。** 你若 `sort` 时从大到小，却用默认 `lower_bound`（按 `<`），结果是错的。降序数组要传自定义比较，入门期更简单的办法是：**升序排，查询也按升序想。**

「最后一个 ≤ x」怎么找？先 `upper_bound` 找到第一个 > x，再往左退一格：

```cpp
auto it = upper_bound(a.begin(), a.end(), x);
if (it == a.begin()) {
    // 全部 > x，没有 ≤ x
} else {
    --it;  // 现在 *it 是最后一个 ≤ x
}
```

退格之前必须确认不是 `begin()`。这和「不能解引用 end」是一对对称的坑。

### 3. 手写二分：只记一种不会打结的

STL 够用时优先 STL。但二分的对象一旦不是数组元素——比如「答案本身是一个整数长度」——你就得手写。实验室里死循环、差一、`mid` 溢出，基本都出在这里。

推荐记 **「找第一个使 check 为真」的闭区间板子**。先保证 `check` 具有单调性：存在一个分界，左边全假、右边全真（或反过来，反过来就取反）。

```cpp
// 在 [L, R] 里找第一个让 check(mid)==true 的 mid
// 如果全部为假，返回 R+1（哨兵）
int first_true(int L, int R) {
    int ans = R + 1;
    while (L <= R) {
        int mid = L + (R - L) / 2;  // 不要写成 (L+R)/2
        if (check(mid)) {
            ans = mid;
            R = mid - 1;  // 还想更左
        } else {
            L = mid + 1;
        }
    }
    return ans;
}
```

为什么这么写：

- **`L <= R` 是闭区间。** 每次要么 `R = mid-1`，要么 `L = mid+1`，`mid` 被排除，区间严格缩小，不会死循环。
- **真的时候先记下再往左。** `ans` 始终是「目前找到的最左的真」。循环结束就是答案。
- **假的时候扔掉左半含 mid。** 因为单调：mid 为假，左边更假。
- **`L + (R - L) / 2`。** `L`、`R` 都是 `int` 且接近 2×10^9 时，`(L + R) / 2` 会溢出成负数，`mid` 飞到外太空，循环开始跳脱衣舞。加法放进 `long long` 也行：`(int)(((long long)L + R) / 2)`。

在数组上找第一个 ≥ x，就是把 `check(mid)` 定义成 `a[mid] >= x`，`L = 0`，`R = n - 1`。你会发现这和 `lower_bound` 是同一句话。

反面教材（不要抄进模板）：

```cpp
// 危险：真的时候写 L = mid，闭区间可能死循环
while (L < R) {
    int mid = (L + R) / 2;
    if (check(mid)) L = mid;
    else R = mid - 1;
}
```

当 `L = R - 1` 且 `check` 为真，`mid` 算出来还是 `L`，`L = mid` 原地踏步。赛时加 `while (clock())` 都救不了，只能改板子。

### 4. 二分答案：把「答案」当成有序数组

有一类题，问的不是「x 在不在数组里」，而是「最小的某个值是多少」：

> 有若干棵树，第 i 棵高 `h[i]`。你每次把一棵树砍掉长度 `M` 的一段（树比 M 矮就砍不到）。问：M 最大能取多少，才能得到总长度不少于 `S` 的木头？

（洛谷 [P1873 砍树](https://www.luogu.com.cn/problem/P1873) 就是这个味道。）

观察：M 越大，得到的木头越少。于是：

- `check(M) = 「砍长度为 M 时，木头总量 ≥ S」`
- M 小：容易真；M 大：容易假
- 我们要**最大的真**（注意：上一节板子找的是最小的真；要最大的真，真的时候往右走，或者对 `check` 取反）

找「最大的真」的对称板子：

```cpp
bool check(long long m);  // 砍高度 m 时木头够不够

long long last_true(long long L, long long R) {
    long long ans = L - 1;
    while (L <= R) {
        long long mid = L + (R - L) / 2;
        if (check(mid)) {
            ans = mid;
            L = mid + 1;  // 还能更高吗？
        } else {
            R = mid - 1;
        }
    }
    return ans;
}
```

`check` 本身是线性扫一遍树高，`O(n)`；外层二分大约 30 次（2^30 > 10^9），总复杂度 `O(n log V)`。这就是为什么 n = 1e6、高度 1e9 仍然能过。

入门期写二分答案，建议每次在纸上画一条数轴：

```
假  假  假  真  真  真  真
            ↑
         我们要的分界
```

先问自己要左端还是右端，再决定「为真时往哪边缩」。不要一边写代码一边现场发明。

`L`、`R` 的初值从题意来：砍树时，`L = 0`，`R = max(h[i])`。故意把右端多放一点（例如 `max(h)+1`）当哨兵，比卡在边界上少很多 Off-by-one。

### 5. 浮点数：少用，用就固定次数

实数域没有「下一个整数」，`L <= R` 可能因为精度永远不相等。入门做法是**循环固定次数**（例如 80～100 次），而不是 `while (R - L > 1e-9)` 这种和误差纠缠的写法：

```cpp
for (int it = 0; it < 80; it++) {
    double mid = (L + R) / 2;
    if (check(mid)) R = mid;
    else L = mid;
}
```

80 次之后区间已经细到荒谬。输出时按题面 `printf("%.10f\n", L)` 即可。本篇不展开；见到「保留 6 位小数、答案是一个实数」再回来抄这段。

### 6. 和 sort 的契约

二分是寄居蟹，壳必须是「有序」。

- 读入后**先 `sort` 再查**。漏了 sort，样例若碰巧有序，你会获得虚假的自信。
- `unique` 去重后再二分，适合「值域压缩」「离散化」——那是后话，但你会在并查集、线段树题里再遇见。现在知道「有序 + 去重之后，lower_bound 返回的下标可以当新编号」就够。
- 对 `vector<pair<int,int>>` 二分，默认按 `first` 再 `second`。你若只想按 `first` 找，要自己写比较，或把 key 抽成单独的 `vector<int>`。入门题尽量抽一层，少和 `pair` 的比较规则搏斗。

### 7. 复杂度直觉（面试和赛时都用得上）

| 操作 | 复杂度 | n=2e5 时 |
| --- | --- | --- |
| 扫一遍找 x | O(n) | 一次可以，n 次询问不行 |
| 排序 | O(n log n) | 付一次门票 |
| 之后每次 `lower_bound` | O(log n) | 大约 18 次比较 |
| 二分答案，`check` 为 O(n) | O(n log V) | V=1e9 大约 30 轮 |

log₂(1e6) ≈ 20，log₂(1e9) ≈ 30。所以看到 1e9 的值域，不要怕，怕的是你每轮 `check` 写成了 O(n²)。

### 8. 把题面翻译成二分的现场口诀

1. 有没有「单调」？多给一点资源，局面只会更好/更差，不会跳着变。
2. 问的是「最小的可行」还是「最大的可行」？
3. `check(mid)` 能不能 O(n) 或 O(n log n) 判掉？
4. 边界：0、1、n、max、min、取不到时的哨兵。
5. 先用数组 `{1,2,2,2,4,5}` 手跑一遍，再交。

如果第 1 步就没有单调（例如「恰好等于 k 个」这种非单调），不要硬二分，那是另一类题。

## 常见坑 / 注意事项

- **没排序就 `lower_bound`。** 标准库**不检查**有序。未定义的不是 crash，是静悄悄的错答案。
- **解引用 `end()`。** 找不到时先判断。
- **`while (L < R) R = mid` 与 `L = mid` 混用。** 死循环专杀赛时心态。用本篇「记 ans + 闭区间每次丢掉 mid」。
- **`(L + R) / 2` 溢出。** 改 `L + (R - L) / 2`，或全程 `long long`。
- **`check` 里用了 `int` 乘 `int`。** 木头长度、距离平方先升 `long long`。二分对了，乘法溢出仍 WA。
- **要「最大」却抄了「最小」的板子。** 画数轴。真的时候往哪边缩，写错一次就整题反了。
- **`lower_bound` 的区间写成 `a.end() - 1`。** STL 也是左闭右开，传 `a.end()` 才覆盖最后一个元素。
- **询问很多却每次重新 `sort`。** 排一次，查一万次。
- **用 `== x` 当 `check` 去二分。** 「等于」不是单调谓词（假假真假假），会漏。等于用 lower 再验证，或 `binary_search`。
- **浮点 `while (R - L > eps)` 加步长不收敛。** 改固定次数。
- **样例只有一组有序数据。** 自己造一组乱序、一组全相等、一组找不到、一组 x 小于全体、一组 x 大于全体。五组过了再交，比交十次 WA 便宜。

## 趣味课间：实验室经典翻车集

- **「STL 背叛了我。」** 没有。是数组没排。STL 假定你是个守法公民。
- **「我本地对了。」** 本地输入文件只有样例。把 `n=1`、`x` 比所有数都小、所有数都相等这三种存成 `in2.txt` 再跑。
- **「二分好高级，我用 map 好了。」** `map` 内部也是树，单次也是 O(log n)，但常数和内存都更大；有序数组 + 二分在竞赛里更常见、更好写。该用 `map` 的是「动态插入再查询」。别用大炮打已经排好的静态数组。
- **「log 那么小，我线性扫也行吧。」** 单次行。套在 n 次询问外面就不行。CF 的 2 秒时限对 4e10 次操作没有慈悲。

## 小结

排序是买票，二分是入场。`lower_bound` / `upper_bound` 把「第一个 ≥ / >」变成一行；手写板子把同一句话用在「答案本身」上。先会翻译题面，再选 STL 还是手写。

建议练习（由易到难，不必一天打完）：

- 洛谷 [P2249 【深基13.例1】查找](https://www.luogu.com.cn/problem/P2249)：有序数组上查是否存在，体会 `lower_bound`
- 洛谷 [P1678 麻烦的高考志愿](https://www.luogu.com.cn/problem/P1678)：每个数找最近的，练 `lower_bound` 左右邻
- 洛谷 [P1873 砍树](https://www.luogu.com.cn/problem/P1873)：二分答案入门
- 自己对 `{1,2,2,2,4,5}` 把 x = 0, 2, 3, 5, 100 的 lower / upper 下标全部手算一遍，再跑程序对答案——这五分钟比交三道 WA 值钱
