# 字符串哈希：把一段字符变成一个整数

> 读完你应该能：预处理前缀哈希，用 O(1) 取出任意子串的哈希；用它做匹配、判相等、二分最长公共前缀；知道单哈希可能被卡，双哈希或好模数能降低风险。
>
> 一句口号：**子串哈希 = 两个前缀的差，再乘上进制的幂，和数字的前缀和是同一张皮。**

## 背景 / 为什么要读这篇

[KMP](KMP.md) 匹配是线性、确定的。很多题要的不是「模式出现在哪」，而是「这两个区间是不是同一段字符」「从 i、j 出发最长公共前缀多长」。每次 `substr` 再比较是 O(n²)。

把字符串看成 base 进制数，一段子串对应一个整数。预处理前缀后，任意区间的「数值」O(1) 拿出来。这和 [前缀和](前缀和与差分.md) 几乎同一句话，只是减法前要补齐位数。

实验室有人 `base=10` 只对数字串；有人模数用 `1e9+7` 且 base=26 被精心构造卡掉。赛时双哈希是礼貌，不是偏执。

## 正文

### 1. 多项式哈希

字符映射成 1..26 或直接 `s[i]+1`（避免 0 导致前导零混淆）。选定进制 `B`（常见 131、13331）和模数 `M`（1e9+7、1e9+9，或 2^64 自然溢出）。

```text
h[i] = s[1]*B^{i-1} + s[2]*B^{i-2} + ... + s[i]*B^0     (前 i 个的哈希)
```

另一种更常用：左高位，

```text
h[i] = h[i-1] * B + s[i]
```

则子串 `s[l..r]`（1-based）为：

```text
hash(l,r) = h[r] - h[l-1] * B^{r-l+1}
```

模意义下减法加 M 再模。`p[k] = B^k` 预处理。

### 2. 模板（1-based，单模）

```cpp
struct SH {
    static const long long M = 1000000007LL;
    static const long long B = 131;
    vector<long long> h, p;
    SH(const string& s) {
        int n = (int)s.size();
        h.assign(n + 1, 0);
        p.assign(n + 1, 1);
        for (int i = 1; i <= n; i++) {
            h[i] = (h[i - 1] * B + (s[i - 1] - 'a' + 1)) % M;
            p[i] = p[i - 1] * B % M;
        }
    }
    long long get(int l, int r) {  // 闭区间，1-based
        long long x = (h[r] - h[l - 1] * p[r - l + 1]) % M;
        if (x < 0) x += M;
        return x;
    }
};
```

比较 `s[l1..r1]` 与 `s[l2..r2]`：长度先等，再 `get` 相等。不等长必不等（除非你做的是循环同构等别的题）。

**自然溢出**（unsigned long long，模 2^64）：更快，无需 `%`，CF 上偶发被卡。区域赛模板题单模 1e9+7 常常够；被卡再双模。

### 3. 双哈希

两个 `(B,M)` 对，子串相等当且仅当两个 `get` 都相等。碰撞概率近乎 1/(M1 M2)。

```cpp
pair<long long, long long> get2(int l, int r);
```

不要两个模都用偶数或都用小素数。`M1=1e9+7, M2=1e9+9`，`B` 可同可不同。

### 4. 匹配：Rabin-Karp

文本每个长度为 m 的窗口 `get(i, i+m-1)` 与模式哈希比较。O(n)。和 KMP 同阶，实现短，适合「很多模式、先滤一下」或「还要别的区间比较」。需要所有出现位置且防卡，KMP 更干净。

滑动窗口哈希：`h' = (h - s[l]*p[m-1]) * B + s[r+1]`，注意减完加 M。

### 5. 二分 LCP

从位置 i、j 出发的最长公共前缀：二分长度 mid，判断 `get(i,i+mid-1)==get(j,j+mid-1)`。O(log n) 每次。后缀排序、最长重复子串常用这招，和 [二分](lower_bound与二分.md) 同一肌肉。

### 6. 和 KMP 怎么选

| 需求 | 选 |
| --- | --- |
| 单模式所有出现，要确定 | KMP |
| 任意子串相等、LCP、集合里查串 | 哈希 |
| 多模式 | AC 自动机，或哈希丢进 set |
| 被卡风险 | 双哈希 / KMP |

哈希是概率算法（模 2^64 或单模）。学术上存在冲突；竞赛里双哈希 + 奇数进制，被卡很少。不要用 `hash = hash*10 + (s[i]-'0')` 还不取模，那是整数溢出赌博。

## 常见坑 / 注意事项

- **`h[r]-h[l-1]*p[...]` 减成负数没加 M。**
- **字符映射成 0。** `a=0` 时 `"a"` 和 `""` 前缀可能糊。用 `+1`。
- **0-based / 1-based 和 `s[i-1]`。**
- **长度不同仍比哈希。**
- **`B=10` 只适合数字，字母会撞。**
- **`int` 存 `h[i]*B`。**
- **单哈希 CF 被卡还骂出题人。** 换双哈希。
- **把 STL `hash<string>` 当竞赛哈希。** 实现依赖、易卡、不能 O(1) 子串。

## 趣味课间：实验室经典翻车集

- **「哈希比 KMP 高级。」** 不是高级，是另一把刀。匹配用 KMP 心安，区间相等用哈希方便。
- **样例全是短串。** 冲突藏在 n=1e5。本地对拍两份随机串。
- **`unsigned long long` 当有符号输出。** 比较用 `==`，不要当负数排序当钥匙除非你知道自己在做什么。
- **预处理 `p[i]` 用 `qpow` 每次。** O(n log) 没必要，递推 `p[i]=p[i-1]*B`。

## 小结

前缀哈希 + 幂数组，子串 O(1)。减法补模。比较相等先比长度。要确定无冲突走 KMP；要灵活切子串走哈希，重要场次双模。
