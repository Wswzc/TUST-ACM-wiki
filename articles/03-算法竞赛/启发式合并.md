# 启发式合并：小的并进大的，均摊少抄一遍

> 读完你应该能：在集合合并时把小的 `map`/`vector` 插进大的，说出为什么总复杂度是 O(n log n)；在树上用「重儿子留下、轻儿子算完丢掉」做 DSU on tree；分清它和 [树链剖分](树链剖分入门.md) 都认重儿子，但一个留信息、一个剖编号。
>
> 一句口号：**每次把较短的那一截搬进较长的那一截。每个元素被搬的次数不超过 log。**

## 背景 / 为什么要读这篇

[并查集](并查集.md) 的按秩合并已经是启发式：小树挂到大树上。[线段树](线段树入门.md) 能维护能合并的信息。子树里「颜色种类、众数、最远点对」这类，线段树不好装，暴力是每个点扫一遍子树，O(n²)。

启发式合并：算完轻子树就丢掉，重子树的统计**留在身上**给父亲用，轻的再插入一遍。实验室有人每次 `cnt.clear()` 把重儿子也清了；有人合并两个 `map` 时无脑 `for (a) b[k]+=v` 却让 a 比 b 大。本篇先集合，再树上。

## 正文

### 1. 集合：小的插入大的

两个 `std::map`（或 `vector` 再 unique），合并后只要一份：

```cpp
void merge(map<int, int>& a, map<int, int>& b) {
    if (a.size() < b.size()) swap(a, b);  // a 始终是大的
    for (auto [k, v] : b) a[k] += v;
    b.clear();
}
```

`swap` 只换容器句柄，O(1)。随后只遍历**小的**。

一个元素从大小 1 的集合出发，每次被并进至少翻倍的集合，被搬 O(log n) 次。n 次合并，总插入 O(n log n)（再乘 map 的 log）。

这就是启发式。按时间顺序瞎合并、每次把左边拷进右边，最坏 O(n²)。

### 2. 树上 DSU on tree

问题形状：对每个点 u，问**子树**里某种统计（颜色种数、出现次数最多的颜色之和……），且统计能靠「加一个点 / 删一个点」维护——和 [莫队](莫队.md) 的 `add`/`del` 同一肌肉。

[树链剖分](树链剖分入门.md) 的 dfs1 已经标过 `son[u]`（最重的儿子）。DSU on tree：

1. 先递归所有轻儿子，算完**清空**计数（轻子树的答案已经在 `ans[v]`）。  
2. 再递归重儿子，**不清空**。  
3. 把轻儿子子树重新 `add` 进来，再 `add` u 自己。  
4. 此时计数 = u 的整棵子树，记下 `ans[u]`。  
5. 若 u 不是父亲的重儿子，离开时再清空。

重儿子已经在 `cnt` 里，**不要再扫一遍重儿子**。

```cpp
int sz[N], son[N], col[N], ans[N];
int cnt[N], kinds;

void dfs_sz(int u, int p) {
    sz[u] = 1;
    son[u] = 0;
    for (int v : g[u]) {
        if (v == p) continue;
        dfs_sz(v, u);
        sz[u] += sz[v];
        if (sz[v] > sz[son[u]]) son[u] = v;
    }
}

void add_tree(int u, int p, int coef) {
    int c = col[u];
    if (coef == 1) {
        if (++cnt[c] == 1) kinds++;
    } else if (--cnt[c] == 0) kinds--;
    for (int v : g[u])
        if (v != p) add_tree(v, u, coef);
}

void dfs(int u, int p, bool keep) {
    for (int v : g[u])
        if (v != p && v != son[u]) dfs(v, u, false);
    if (son[u]) dfs(son[u], u, true);
    for (int v : g[u])
        if (v != p && v != son[u]) add_tree(v, u, +1);
    {
        int c = col[u];
        if (++cnt[c] == 1) kinds++;
    }
    ans[u] = kinds;
    if (!keep) add_tree(u, p, -1);
}
```

`add_tree(u,p,-1)` 会把 u 整棵子树减掉（含重儿子），因为不 keep 时父亲不需要这棵轻子树的计数。

复杂度：每个点作为轻儿子子树被重新扫描时，所在子树大小至少翻倍（相对父亲重链方向），每个点被暴力扫 O(log n) 次，总 O(n log n)。再乘 `cnt` 操作。

### 3. 和树剖、莫队怎么选

| 问 | 更可能 |
| --- | --- |
| 路径点权、带改 | 树剖 + 线段树 |
| 子树某种不好合并的统计、无改 | DSU on tree |
| 子树颜色、要合并两棵线段树 | 线段树合并（也是启发式：小根植到大根） |
| 欧拉序上的区间 | 莫队 |

同一道「子树颜色」可能三种都能写。入门先会小 map 合并，再写 keep 重儿子。

## 常见坑 / 注意事项

- **合并时遍历大的往小的插。**  
- **`keep=false` 却不清 cnt。** 下一棵轻子树脏数据。  
- **重儿子算完又 `add_tree` 一遍重儿子。** 颜色计数翻倍。  
- **`son[u]` 未初始化，0 号点当重儿子。** `son` 赋 0 或 -1 要和点号错开。  
- **根的 `keep` 随便 true。** 整棵树算完可以不清。  
- **`add_tree` 递归爆栈。** n=1e5 链，扩栈或改 dfs 序扫 `[dfn,dfn+sz)`。

## 趣味课间：实验室经典翻车集

- **「启发式就是并查集。」** 并查集是一个例子。map、线段树、树上 cnt 都是。  
- **样例菊花图，一个重儿子。** 轻儿子扫描次数看不出来。造一条链挂一朵小菊花。  
- **`swap(a,b)` 之后还用旧的迭代器。** 迭代器作废。  
- **复杂度写成 O(n²) 自己吓自己不敢写。** 均摊 log，1e5 能过。

## 小结

小的并进大的，元素被搬 O(log n) 次。树上：轻儿子算完扔，重儿子留下，再把轻的扫进来。和树剖共用 `son[]`，信息不走线段树。
