# 贪心入门：局部最优什么时候等于全局最优

> 读完你应该能：认出「排序之后从左到右做选择」这一类题；会写活动安排、区间覆盖的入门板子；遇到硬币问题知道贪心可能是错的；能用一句话解释**交换论证**——为什么先选这个不会更差。
>
> 一句口号：**贪心不是感觉，是证明过（或被数据打过）的选择策略。感觉对了却没证明，叫赌。**

## 背景 / 为什么要读这篇

[前缀和](前缀和与差分.md) 把重复计算砍掉；[二分](lower_bound与二分.md) 把搜索空间砍半。贪心更蛮横：**每一步只看眼前最好的，且宣称最后也是最好的。**

这听起来像人生建议，也因此每年都有人在赛场上「感觉应该先拿最大的」然后 WA。贪心题的分界不在代码长度——常常十几行——而在你敢不敢说：

> 存在一份最优解，经过若干次交换后，能变成我的贪心解，且答案不变差。

本篇用几个实验室反复打的模型把这句话落地。证明不必写进论文，但你要能讲给队友听。讲不出来，就当它可能是 DP。

## 正文

### 1. 先看一个会骗人的例子：硬币

面额 `{1, 5, 10, 12}`，要凑 15。贪心「每次拿不超过剩余的最大面额」：12 + 1×3 = 4 枚。实际上 10 + 5 = 2 枚。

人民币 `{1,5,10,20,50,100}` 碰巧对贪心友好（这是设计过的）。题目给的面额没有保证。**看见「最少用多少枚硬币」不要无脑贪心**，那是完全背包 / DP 的地盘。

结论：贪心策略必须和题目结构绑定。换一组数据就错的策略，不是策略，是运气。

### 2. 最经典的真贪心：活动安排（选最多不相交区间）

n 场活动，第 i 场占用 `[l_i, r_i)`（或闭区间，注意端点是否可衔接）。一场只能参加一个，问最多参加几场。

策略：**按结束时间从早到晚排序，能选就选。**

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<pair<int, int>> a(n);  // {结束, 开始}
    for (int i = 0; i < n; i++) {
        int l, r;
        cin >> l >> r;
        a[i] = {r, l};
    }
    sort(a.begin(), a.end());  // 结束早的在前

    int ans = 0;
    int last = -2e9;  // 上一个选中的结束时间
    for (auto [r, l] : a) {
        if (l >= last) {  // 与上一场不冲突；闭区间改成 l > last
            ans++;
            last = r;
        }
    }
    cout << ans << '\n';
    return 0;
}
```

为什么对？交换论证的口语版：

假设最优解里第一场不是「结束最早且能选的那场」G，而是某场 X。G 结束得更早，把 X 换成 G，后面腾出的时间只多不少，不会让最优解变差。于是存在一份最优解包含 G。删掉 G，对剩下的问题同样贪心……归纳下去，贪心解就是最优解。

按开始时间早排序、按长度短排序，都可以造反例。**策略错了，代码再短也是 WA。** 赛时若你不能用「换成结束更早的不会更差」说服自己，就先造两组数据打自己的程序。

### 3. 区间覆盖：用最少线段盖住 `[1, t]`

经典变种：每条线段 `[l, r]`，选尽量少的条数覆盖目标区间。策略往往是：在当前还没盖到的点，选「能盖住这一点、且右端点最远」的线段。

实现：按左端点排序，维护「现在盖到哪儿」，在所有 `l <= 当前` 的线段里取最大的 `r`。取不到就失败。

这和活动安排的味道相反：一个是「尽快结束腾地方」，一个是「尽量伸得远」。**都叫贪心，排序关键字完全不同。** 做题时先问覆盖还是选不相交，再决定按哪一端排。

### 4. 排序之后扫一遍：更多「同一骨架」的题

很多贪心长这样：

1. 定义每个物品的「优先级」（比值、结束时间、截止日期……）
2. `sort`
3. 从左到右能做就做，用一个变量维护状态（时间、容量、上一结束点）

例子（不必现在全做）：

| 题型 | 常见关键字 | 维护什么 |
| --- | --- | --- |
| 活动安排 | 结束时间升序 | 上一次结束 |
| 截止日期作业 | 截止早或价值密度 | 当前时刻 |
| 排队打水 | 时间短的先 | 已等待总和 |
| 合并果子 | 每次选最小两堆 | 优先队列 |

排队打水：n 个人打水时间 `t[i]`，总等待（含自己）之和最小。策略：`t` 升序。证明：相邻两个人若前面那个更慢，交换后总和严格变小。于是最优解必是升序——又是交换。

合并果子（洛谷 [P1090](https://www.luogu.com.cn/problem/P1090)）：每次合并两堆，花费为两堆之和。策略：始终合并当前最小的两堆。实现要用 `priority_queue`（小根堆），语言线下一篇会写。这里只要记住：**贪心的选择经常长得像「每次取最值」，最值动态变化时，set / 优先队列上场。**

### 5. 和 DP、二分的边界

| 你发现…… | 更可能是 |
| --- | --- |
| 每一步有一个「显然」的选择，交换不变更差 | 贪心 |
| 选择有后效，当前决定改变未来可选项的结构且不能交换 | DP |
| 问「最小的最大」「最大的最小」，check 具有单调性 | 二分答案 + 贪心 check |

第三行很常见：把答案二分下去，`check(mid)` 里面用贪心判断「mid 是否可行」。砍树、跳石头都是这个形状。[二分那篇](lower_bound与二分.md) 的 `check` 往往就是一段贪心。

**先写暴力再优化。** n 很小的样例，用 DFS 搜最优，和贪心对拍。贪心没有对拍，就是没上保险的钢丝。

### 6. 怎么在纸上找策略（赛时十分钟）

1. 极端数据：全重叠、全不相交、一个包含另一个。
2. 问自己：最优解里第一个决策，能不能换成我贪心选的那个？
3. 能换成：大概率对，再找一个反例折磨它。
4. 换不成：举一个反例，换关键字，或放弃贪心。
5. 反例比证明更便宜。先当敌人再当作者。

## 常见坑 / 注意事项

- **按错误的关键字排序。** 活动安排按开始时间：反例是「一场很长的早场占掉后面两场短的」。
- **端点开闭写错。** `l >= last` 与 `l > last` 差在「一场结束的瞬间能否开始下一场」。看题面。
- **贪心过了样例。** 样例往往不会打你。自己造「包含 / 相切 / 完全相同区间」。
- **硬币问题套人民币直觉。** 面额一变就错。
- **需要全局最优却用了「每步最大价值」而忽略代价。** 价值密度 vs 价值本身，分数背包和 0-1 背包不是同一个贪心。0-1 背包贪心是错的，那是 DP。
- **`int` 累加等待时间。** 排队打水的总和容易爆，`long long`。
- **证明不会写就不敢交。** 入门赛可以交，但交完用对拍；区域赛里没证明的贪心是定时炸弹。

## 趣味课间：实验室经典翻车集

- **「贪心不就是 sort 吗？」** sort 是手段。没策略的 sort 只是把 WA 排得整整齐齐。
- **「我证明不了但 CF 过了。」** 可能数据弱。把策略写成注释两行，下一场同类题才能复制直觉。
- **「反例想不出来所以是对的。」** 想不出来只说明你还不是出题人。对拍吧。
- **田忌赛马。** 齐王上中下，田忌下上中。这也是贪心（或博弈）：用最差的去消耗对方最好的，其余对位。生活例子有时比公式好记，但赛时仍要落到比较器和循环。
- **「这题贪心，那题也 sort，我全 sort。」** 图论最短路、DP 转移，sort 解决不了拓扑以外的问题。工具认题，不要认排序。

## 小结

贪心 = 排序关键字 + 一次扫描 + 一段「为什么交换不变差」。活动安排按结束时间，覆盖按「当前点伸得最远」，硬币默认不贪。能对拍就对拍，见 [对拍](../00-团队指南/对拍.md)。

建议练习：

- 洛谷 [P1803 凌乱的 yyy](https://www.luogu.com.cn/problem/P1803)：活动安排几乎原题
- 洛谷 [P1090 合并果子](https://www.luogu.com.cn/problem/P1090)：贪心 + 优先队列
- 洛谷 [P1223 排队接水](https://www.luogu.com.cn/problem/P1223)：短作业优先
- 自己给活动安排写一个「按开始时间排序」的错误版本，造一组让它输给正确贪心的数据——这比 AC 三道同质题更长记性
