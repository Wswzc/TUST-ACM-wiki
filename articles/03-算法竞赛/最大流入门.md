# 最大流入门：水管里能挤过去多少

> 读完你应该能：画残量网络、解释反向边为什么存在；用 EK（BFS 增广）求出最大流；知道 Dinic 多层图为什么更快；把二分图匹配看成单位容量网络。
>
> 一句口号：**能增广就还能多送水。反向边不是把水抽回去玩，是给算法一个「反悔」的会计科目。**

## 背景 / 为什么要读这篇

流量问题：源点 s 产水，汇点 t 收水，每条管道有容量。最大流 = 不撑破管子的前提下 s 到 t 的最大吞吐量。

它是 [二分图匹配](二分图匹配.md) 的爹：匹配边容量 1 的网络最大流。也是费用流、最小割的入口。最小割 = 最大流（对偶），很多「最小代价拆点/拆边」题其实在求割。

实验室有人建边忘了反向边容量 0；有人增广完不改残量。本篇用 EK 讲清楚，Dinic 给可交模板但不展开证明。

## 正文

### 1. 残量与反向边

边 `u→v` 容量 c，当前流量 f，残量 `c-f`。再想多送，只能走还有残量的边。

反向边 `v→u` 初始容量 0。一旦 `u→v` 流了 f，反向残量变成 f：表示允许把这 f 撤回来。增广路走反向边 = 悔流，和匈牙利让人改配是同一哲学。

实现：邻接表存边结构 `{to, cap, rev}`，`rev` 是反向边在对面 vector 里的下标。加边时正反一起加。

```cpp
struct Edge { int to, rev; long long cap; };
vector<vector<Edge>> g;

void add_edge(int u, int v, long long c) {
    g[u].push_back({v, (int)g[v].size(), c});
    g[v].push_back({u, (int)g[u].size() - 1, 0});
}
```

无向管：正反都设成 c，或按题意。竞赛多为有向。

### 2. EK：BFS 找增广路

每次 BFS 在残量网络里找 s 到 t 的路，瓶颈 `d` = 路上最小残量，沿路减正向、加反向，累加进答案。直到 BFS 走不到 t。

```cpp
const long long INF = 4e18;
int n, s, t;
vector<int> par, pe;  // 前驱点、前驱边下标

bool bfs() {
    par.assign(n + 1, -1);
    queue<int> q;
    q.push(s);
    par[s] = s;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int i = 0; i < (int)g[u].size(); i++) {
            auto& e = g[u][i];
            if (e.cap > 0 && par[e.to] == -1) {
                par[e.to] = u;
                pe[e.to] = i;
                q.push(e.to);
                if (e.to == t) return true;
            }
        }
    }
    return false;
}

long long maxflow() {
    long long flow = 0;
    pe.assign(n + 1, 0);
    while (bfs()) {
        long long d = INF;
        for (int v = t; v != s; v = par[v])
            d = min(d, g[par[v]][pe[v]].cap);
        for (int v = t; v != s; v = par[v]) {
            Edge& e = g[par[v]][pe[v]];
            e.cap -= d;
            g[v][e.rev].cap += d;
        }
        flow += d;
    }
    return flow;
}
```

复杂度 O(n m²) 量级，n≤200、m 不大时稳。再大用 Dinic。

### 3. Dinic 在干什么（入门只需印象）

先 BFS 分层：只允许走到 `dep[v]=dep[u]+1` 的边，避免瞎走。再 DFS 多路增广，当前弧优化（边指针不回头）。复杂度好于 EK，二分图上往往很快。模板见 OI Wiki / 洛谷 P3376 题解，默写 EK 能讲残量，再抄 Dinic 才抄得明白。

### 4. 最小割

删除一些边使 s、t 不连通，容量和最小。最大流最小割定理：该值 = 最大流。

求完最大流后，残量网络里 s 能到达的点构成 S，其余为 T。S→T 的原边就是一组最小割。输出方案用这招。

建模：拆点（点容量变成入边到出边）、源汇连法，比写 Dinic 更考功力。先会算一个已知网络的数值。

### 5. 建模速查

| 题 | 建图 |
| --- | --- |
| 二分图匹配 | s-左-右-t，容量 1 |
| 每条边最多用一次的路径条数 | 单位容量最大流 |
| 点有容量 | 拆成 in→out |
| 最小割关闭工厂 | 收益连源、代价连汇，求割 |

费用流 = 边带费用，最短路增广。入门先最大流，再读 [费用流入门](费用流入门.md)。

## 常见坑 / 注意事项

- **反向边 cap 初始成 c。** 有向边应为 0。  
- **增广只减正向。** 必须对称加反向。  
- **`int` 流量。** 边权 1e9、路径叠。  
- **多组数据 `g` 没清。**  
- **s、t 编号与 n。** 点从 0 还是 1。  
- **无增广仍有「看起来能走」的原图边。** 看残量不是原容量。  
- **n=1e5 用 EK。** TLE。Dinic 或改算法。

## 趣味课间：实验室经典翻车集

- **「反向边把水送回 s 了。」** 会计上的负账，不是物理倒流。  
- **样例一条路。** 任何实现都对。造一个必须悔流的：s-a-t 容量 1，s-a-b-t 更大，顺序不同要靠反向边纠错。  
- **匹配题上 Dinic 一百行。** n 小匈牙利二十行。  
- **最小割输出成最大流数值就交。** 题要方案时还得划分 S/T。

## 小结

残量 = 还能送多少；反向边 = 允许反悔。EK 反复 BFS 增广到走不动。小图 EK，大图 Dinic。匹配是单位网络。最小割与最大流同值。
