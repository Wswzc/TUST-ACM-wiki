# 并查集：谁和谁是一伙的

> 读完你应该能：写出带路径压缩的 `find` 和按秩（或随手）`unite`；用它维护连通性、判环、处理「加边后是否联通」；知道并查集不擅长删边；能把「食物链 / 带权」当成进阶而不是第一天的必做。
>
> 一句口号：**find 问队长是谁，unite 让两队合并。路径压缩把长队变成星形，几乎 O(1)。**

## 背景 / 为什么要读这篇

[新人指南](../00-团队指南/新人指南.md) 把并查集放在「第 1 年结束」的数据结构里，不是因为它难写——模板十几行——而是因为它换皮题极多：朋友圈、城市修路、最小生成树的 Kruskal、程序自动分析、食物链。

核心就一个抽象：**一堆元素被分成若干组，支持「合并两组」和「查询是否同组」。** 不能高效拆组。加边容易，删边请换题或换算法。

实验室有人 `find` 写成 `return fa[x];` 不递归，于是路径从不压缩，也从不真正找到根。还有人 `unite` 写成 `fa[x]=y` 没找根，树变成随机图，RE 或 WA 看心情。本篇把根、压缩、合并三件事钉死。

## 正文

### 1. 森林：每个集合是一棵倒挂的树

每个元素记一个 `fa[x]`：上级是谁。根满足 `fa[root] = root`（或 -1，选一种）。一开始每人是自己的根：n 个集合。

`find(x)`：顺着 `fa` 走到根。根相同则同组。

`unite(x,y)`：找到两个根，让其中一个根认另一个做上级。两组合一，集合数减一。

这比 `vector<int> 组成员` 每次合并要拷贝数组便宜得多。

### 2. 最小能跑的模板

```cpp
#include <bits/stdc++.h>
using namespace std;

struct DSU {
    vector<int> fa, rk;  // rk：树高近似，用于按秩合并
    int sets;
    DSU(int n) : fa(n + 1), rk(n + 1, 0), sets(n) {
        iota(fa.begin(), fa.end(), 0);  // fa[i]=i
    }
    int find(int x) {
        if (fa[x] == x) return x;
        return fa[x] = find(fa[x]);  // 路径压缩
    }
    bool same(int x, int y) { return find(x) == find(y); }
    bool unite(int x, int y) {
        x = find(x);
        y = find(y);
        if (x == y) return false;  // 已在同一集合：这条边会成环
        if (rk[x] < rk[y]) swap(x, y);
        fa[y] = x;
        if (rk[x] == rk[y]) rk[x]++;
        sets--;
        return true;
    }
};
```

`iota` 在 `<numeric>`，万能头已包含。不想按秩：随机 `fa[y]=x` 也行，有路径压缩后均摊仍然极快；按秩或按 size 更稳，习惯带上。

**路径压缩：** `find` 路上每个点直接挂到根。下次 O(1)。不要写成：

```cpp
int find(int x) {
    while (fa[x] != x) x = fa[x];
    return x;  // 能找到根，但不压缩，链长了会慢
}
```

迭代压缩可以写成两遍走或「先找根再挂」，递归压缩最常见。n=1e5 链状、不压缩，`find` 是 O(n)，查询 1e5 次就 TLE。

### 3. 三道标准题型

**（1）是否同组 / 朋友的朋友**

读「x 和 y 是朋友」就 `unite`；问「x 和 y 是否朋友」就 `same`。传递性自动成立：A-B、B-C 则 A-C 同根。

**（2）加边判环**

无向图里，若 `unite` 返回 `false`（已经同组还要连边），这条边会在组内成环。Kruskal 最小生成树就是：边按权排序，能 `unite` 成功就选进树，失败则跳过。这是贪心 + 并查集，[贪心](贪心入门.md) 的大型现场。

**（3）连通块个数**

初始 `sets = n`，每次成功 `unite` 减一。或最后扫一遍有多少 `fa[i]==i`（压缩后）。注意：必须对所有点 `find` 一次再数根，否则有的 `fa[i]` 还不是根。

```cpp
int roots = 0;
for (int i = 1; i <= n; i++)
    if (find(i) == i) roots++;
```

### 4. 按 size 合并与「集合大小」

维护 `sz[root]`：

```cpp
// 初始化 sz.assign(n+1, 1);
if (sz[x] < sz[y]) swap(x, y);
fa[y] = x;
sz[x] += sz[y];
```

问「x 所在组有多大」：`sz[find(x)]`。修路、帮派人数、食物份数都用这个。

`rk` 是树高，`sz` 是元素个数，不要混用一个数组当两个含义。

### 5. 不擅长什么

| 操作 | 并查集 |
| --- | --- |
| 合并、查是否同组 | 极快 |
| 查询集合大小 | 维护 sz |
| 删边、把一个点踢出集合 | 不支持（或非常难看） |
| 维护集合内最值 | 可在根上捎带 min/max，合并时更新 |
| 有向关系、敌友三倍经验 | 带权并查集 / 种类并查集，进阶 |

种类并查集：把 `x` 和 `x+n` 当成「x 的敌人」，开 2n 或 3n 个点。食物链 [P2024](https://www.luogu.com.cn/problem/P2024) 是名题，**先把本篇模板打穿再去碰**。第一天就上食物链，容易只记住结论不会 `find`。

### 6. 复杂度

带路径压缩 + 按秩：均摊 `α(n)`，阿克曼反函数，小于 5。当 O(1) 用。

不要在 `find` 里写循环 1e9 次「保险」。也不要每次 `unite` 都 `sort` 全表。

### 7. 和 BFS 连通块、DFS 的分工

网格求连通块：[BFS](BFS网格最短路.md) 洪水填充更直观。一般图、只关心加点加边后的连通、Kruskal、离线「加边询问」，并查集更合适。

动态加边、全程不问删边：并查集。边一开始就在、只遍历：DFS/BFS。

离线删边：倒着当加边，并查集又能用。这是技巧题，知道有这招即可。

## 常见坑 / 注意事项

- **`fa[x]=y` 没 `find`。** 必须挂根。
- **路径不压缩，链卡 TLE。**
- **`find` 写成 `return fa[x]`。** 那只返回父亲，不是根。
- **下标 0/1。** `DSU(n)` 开 `n+1` 且 `iota` 从 0，若点是 1..n，`fa[0]` 浪费即可。
- **多组数据没重建 DSU。**
- **无向图 Kruskal 忘了排序。**
- **`unite` 后用旧的 `x,y` 当根去改 `sz`。** 先 `find` 再认上级。
- **食物链第一天硬刚。**
- **并查集当数组下标 1e9 的 map 用。** 元素值很大先离散化，或 `map` 存 fa，常数变差。点数 1e5、编号 1e9：离散化。

## 趣味课间：实验室经典翻车集

- **「我把所有边 unite 完再 find，中间问过是否同组。」** 顺序错了：询问发生在部分边之后，必须按时间混合处理。离线就把操作排序。
- **「路径压缩改了 fa，rk 还当树高用。」** 压缩后高度信息失真。`rk` 只在 `unite` 时当启发式，压缩不必维护真高度。这就是为什么叫「按秩」不是「按高」。
- **样例两点已经连着，再连一次你当成成功。** 最小生成树会多加边。检查 `unite` 返回值。
- **递归 `find` n=1e5 链、系统栈小。** 极少数环境爆栈。可改迭代压缩，或按秩后几乎没有长链。现代 OJ 少见，但链是好测试。
- **「并查集不就是 DFS 染色吗？」** 静态图上差不多。差在**在线合并**：染色要全图重来，并查集改两下父亲。

## 小结

每人一个父亲，根代表集合。`find` 找根并压缩；`unite` 连根。成功合并减一块、失败加边即环。删边不是它的工作。Kruskal、朋友圈、连通块计数是第一批题。
